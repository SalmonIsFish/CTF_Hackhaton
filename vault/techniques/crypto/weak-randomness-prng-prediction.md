# Weak randomness & PRNG prediction

**Category**: Crypto
**Prevalence**: High — many CTF challenges use weak or predictable RNGs
**Signal**: The challenge generates "random" numbers but either tells you the seed, uses
Python's `random` module (not cryptographically secure), or generates a sequence you can
observe/predict.

## The technique: Python's `random` module (NOT cryptographic)

Python's `random.random()` uses Mersenne Twister, which is predictable if you observe enough
outputs (about 624 consecutive values).

If a challenge uses:
```python
import random
random.seed(some_seed)
token = random.randint(1, 1000000)
```

And you either:
1. Know the seed (hardcoded, printed in source, leaked in config)
2. Can observe several outputs (e.g., 624+ consecutive random numbers)

Then you can recover the internal state and predict all future outputs.

**Tool**: `MT19937Predict` or manual Mersenne Twister state recovery.

## The technique: Linear Congruential Generator (LCG)

If the challenge implements its own "random" number generator:
```
next_state = (a * state + c) mod m
```

This is vulnerable to **truncated linear congruence attack** — if you observe even just 2–3
consecutive outputs, you can often recover `a`, `c`, and `m`, then predict the next number.

## The technique: Weak seed

If randomness is seeded with something predictable:
```python
random.seed(int(time.time()))  # Uses current Unix timestamp
```

The seed space is only ~86,400 values per day (Unix timestamps are 10 digits). An attacker can
brute-force all possible seeds for today and check which one generates the observed sequence.

**Common weak seeds**:
- `int(time.time())` — predictable to the second
- Process ID — often sequential or predictable
- User ID or hostname — both often known
- Hash of a known string — if the string is guessable

## Competition approach

1. **Identify the RNG**: Check source code or infer from challenge description.
2. **Collect outputs**: Observe multiple "random" values generated by the target.
3. **Attempt seed recovery**:
   - If seed is hardcoded or leaked, use it directly.
   - If seed is time-based, brute-force recent Unix timestamps.
   - If seed is from a known source (username, hostname), hash it with common algorithms.
4. **Test state recovery**: If you have 624+ MT19937 outputs, use state recovery tools.
5. **Predict the next value**: Once state is recovered or seed is known, generate the same
  sequence offline and predict future outputs.

## Real gotcha

**Cryptographically secure RNGs** (`secrets` module, `os.urandom()`, `cryptography` library)
are NOT vulnerable to this. If a challenge uses `secrets.randbelow()`, you can't predict it —
the vulnerability must lie elsewhere.

## Tools

- **MT19937Predict**: Python implementation of Mersenne Twister state recovery
- **randcrack**: Tool for predicting MT19937 outputs
- Python's `secrets` module (reference for what secure randomness should look like)

## Source

Recurring in CTF crypto challenges — developers often use convenient-but-insecure RNGs without
realizing the trade-off.
